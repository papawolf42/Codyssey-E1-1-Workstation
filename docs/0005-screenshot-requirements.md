## 2. 제출 기준

instruction이 로그나 출력으로 대체할 수 있도록 허용하더라도 이번 제출에서는 관련 화면을 모두 스크린샷으로 남긴다. 동일한 요구가 반복되더라도 빌드, 실행, 접속, 로그, 연동 상태를 각각 확인할 수 있도록 다섯 장으로 나눈다.

### Dockerfile 빌드·실행

- instruction 73번과 145번은 같은 요구를 두 위치에서 반복한다.
- 빌드 완료 화면과 컨테이너 실행 화면을 각각 캡처한다.
- 명령어 입력과 성공 출력이 한 화면에 함께 보이도록 한다.

### 포트 매핑

- instruction 74번, 77번, 148번, 203번은 같은 포트 매핑 증거에 관한 문장이다.
- 주소창과 응답 화면이 보이는 브라우저 화면을 첨부한다.
- `curl`과 `docker logs`가 보이는 터미널 화면도 별도로 첨부한다.

### GitHub·VS Code 연동

- VS Code의 Source Control과 GitHub 연동 상태가 보이는 스크린샷 한 장을 사용한다.
- 토큰, 인증 코드, 비밀번호는 화면에 포함하지 않는다.

## 4. 현재 완료 항목의 스크린샷 누락 점검

| 완료 항목 | 현재 증거 | 추가할 스크린샷 | 판정 |
|---|---|---|---|
| 터미널 기본 조작 | 명령과 출력 | 계획 없음 | 완료 |
| Docker 설치·점검 | `docker --version`, `docker info` 출력 | 계획 없음 | 완료 |
| Docker 기본 운영 | 이미지·컨테이너 실행 및 로그 스크린샷과 리소스 출력 | 없음 | 완료 |
| hello-world와 Ubuntu | 실행·종료·`attach`·`exec` 출력 | 계획 없음 | 완료 |
| Dockerfile 빌드·실행 | 빌드 및 실행 출력과 스크린샷 | 없음 | 완료 |
| 포트 매핑 | `curl` 결과와 브라우저 이미지 | `01-port-mapping.png` | 완료 |

사용자가 정한 “대체하지 않고 모두 첨부” 기준에서 현재까지 완료한 Docker 관련 항목의 스크린샷은 모두 준비됐다.

Git 사용자 정보 하위 항목은 완료됐지만 GitHub·VS Code 상위 항목은 아직 미완료다. 이후 `05-vscode-github.png`를 추가하고 상위 항목을 완료 처리한다.
